# Decision log

One line per decision, newest last. Dates are absolute (YYYY-MM-DD).

- 2026-10-30 Repo, package and UI name is `gigcast` (David's instruction; replaces the `soundcheck` codename from the kickoff brief).
- 2026-10-30 TypeScript end to end, no Python: one deployable that serves SSE and the UI from the same process; a second stack would not get to a complete product faster.
- 2026-10-30 SvelteKit 2 pinned by scaffolding with `sv@0.15.1`; the current `sv` CLI generates SvelteKit 3, which the brief did not ask for.
- 2026-10-30 Tailwind 4, `@sveltejs/adapter-node`, pnpm 12, Node >= 22 (development on Node 26; `scripts/*.ts` run on Node's native type stripping, so the probe has zero dependencies).
- 2026-10-30 Charts: ECharts. Maps: MapLibre GL JS with geohash cells decoded by `ngeohash`.
- 2026-10-30 Postgres via Docker Compose locally; the hosted provider is decided at M2 (default leaning Neon).
- 2026-10-30 Git: the first scaffold commit landed on `main` directly (nothing to open a PR against); everything after goes through squash-merged pull requests.
- 2026-10-30 Secrets live in a gitignored local env file; `GOOGLE_APPLICATION_CREDENTIALS` points at a gitignored `_secrets/` folder inside the checkout (also excluded by `.dockerignore`). Only names go in `.env.example`.
- 2026-10-30 Model split for the build itself: Fable orchestrates; Sonnet subagents handle scaffolding and boilerplate. Product models (planner and classifier) are environment variables, see the Vertex finding below.
- 2026-10-30 Vertex: project `n1-data` answers for Claude 4.5/4.6 in `global` and `us-east5`; Claude 5.x models are listed but not enabled for the project. M1 defaults to `claude-opus-4-6` (planner) and `claude-haiku-4-5` (classification) unless David enables 5.5; region default `global`.
- 2026-10-30 Qloo probe caches every raw response in `.cache/qloo-probe/` and replays from it with `QLOO_PROBE_REPLAY=1`; the same cache-first pattern becomes the client's replay mode in M1.
- 2026-10-30 Localities are resolved through `/search?types=urn:entity:locality` with "city, country", verified against the country in `disambiguation`, confirmed by the user on the map, and persisted as entity ids; free text never reaches `/v2/insights` (the "Panama City" query resolves to Florida).
- 2026-10-30 The Qloo client whitelists parameters per entity type because the API silently ignores invalid or misplaced ones (confirmed live).
- 2026-10-30 Pricing guidance uses heatmap `price_level_affinity` per cell (`heatmap.dimensions`) rather than place `price_level`, which is populated on only 2–34% of places.
- 2026-10-30 Venue section: when Qloo returns fewer than three venue-tagged places for a market, it is labeled "no coverage" and the promoter's venue shortlist is used; Qloo places power the partners section instead.
- 2026-10-30 Explainability is requested with several simultaneous signals (artist, locality, demographics) because a single signal always scores 1.
- 2026-10-30 Trends come from `/v2/trending` over the trailing twelve months (the series lags the present), artists only; `bias.trends` is used as a ranking bias for lineup candidates. The `/v2/trends/*` and `/analysis` paths from the brief do not exist on the hackathon host.
- 2026-10-30 Artist-versus-city taste match is computed from tag overlap (artist tags vs. `signal.location` tags); `/v2/insights/compare` is entity-versus-entity only and is used for co-headliner fit.
- 2026-10-30 Demo markets proposed: Guatemala City, Santo Domingo, Mexico City (Panama City as the Central America-only alternative). Awaiting David's pick.
- 2026-10-30 Agent output is split in two: the model emits a `BriefDraft` (narrative, picks, labels, outreach drafts) through `emit_brief`; the server attaches raw artifacts (heatmap cells, demographics, trend series, candidate lists) from the tool registry. The model never re-types bulk data, which keeps tokens low and the data exact.
- 2026-10-30 Grounded verification is enforced server side: every pick labeled `grounded` must name an entity id that a tool call in the same run returned; otherwise it is downgraded to `inferred` and listed in `verification.downgraded`. Sources are filled from the registry, not trusted from the model.
- 2026-10-30 Tool list is fixed and ordered (twelve Qloo tools plus `emit_brief`) and the system prompt is a constant with the tool budget baked in, so the cached prefix is byte-stable across runs; per-run content lives in the user message.
- 2026-10-30 Tool runner settings: streaming on, `eager_input_streaming` on every client tool, adaptive thinking, explicit `output_config.effort` (high for the planner), `thread: false` (full history every turn, no dependency on the threads API on Vertex), `max_iterations` 40, tool budget 36 enforced by the registry with a "call emit_brief now" instruction when exhausted.
- 2026-10-30 Fail soft: a run that never reaches `emit_brief` (refusal, truncation, iteration cap, API error) still produces a brief with a fallback draft whose sections are labeled `no_coverage` and a run status of `partial`, with the artifacts gathered so far attached.
- 2026-10-30 Locality fallback inside tools: `locality_id` preferred, WKT point plus radius otherwise; `qloo_resolve_locality` maps ISO codes to English country names for the search query (the raw code "PA" was ambiguous with Pennsylvania).
- 2026-10-30 The Qloo client validates a 200 body against its schema before caching it, so a malformed response is never served from cache; 400-level bodies are cached (deterministic), 429 and 5xx never.
- 2026-10-30 CLI briefs are written to `.cache/briefs/<id>.{json,events.json,md}` (gitignored); Postgres persistence of briefs, runs and events arrives with the web run in M2.
- 2026-10-30 `/v2/trending` caps `take` at 50 and ignores `page` (verified live). The trending tool asks for the trailing twelve months with `take` 50, which returns the most recent ~9 months of (sparse) points; shorter windows returned nothing.
- 2026-10-30 First live brief (Ricardo Arjona, Guatemala City) took 266 s on `claude-opus-4-6` at effort high with 25 tool calls and 21 Qloo calls; about 200 s was the model composing the draft. Prompt caching verified: ~7.3k cached prefix tokens, 43.8k cache reads across the run.
- 2026-10-30 Second live brief (same inputs) confirmed the fixes: status `complete`, 24 tool calls, 24 Qloo calls with 13 Postgres cache hits, 50 trending points parsed, 15 similar artists parsed, every sponsor carries `[S#]` markers, stdout holds only the Markdown; 313 s end to end.
- 2026-10-30 Demo markets confirmed by David: Guatemala City, Santo Domingo and Mexico City, with Panama City (locality "Distrito Panamá") as the Central America-only swap. They are seeded into `markets` and offered as quick picks on `/new`; any other city Qloo covers still works through the locality search.
- 2026-10-30 David's call: stay on `claude-opus-4-6` as the planner for now; Claude 5.5 stays an env-var switch for later.
- 2026-10-30 Map tiles: OpenFreeMap (`https://tiles.openfreemap.org/styles/positron`), free vector tiles without a key, as the default `PUBLIC_MAP_STYLE_URL`.
- 2026-10-30 M2 run manager: a brief run is started by `POST /api/briefs` and continues in the server process; events are persisted one by one (ordered) and fanned out to SSE subscribers through an in-process hub. The SSE handler replays persisted events after `Last-Event-ID`, follows the hub when the run is local and polls Postgres every 2 s otherwise, so a second instance or a restart still serves the trace.
- 2026-10-30 Cloud Run runs one instance (`--max-instances 1`, `--no-cpu-throttling`, 900 s timeout) because the live hub is per process; the Postgres fallback keeps correctness if that ever changes. Concurrency is capped at two briefs per instance (`MAX_CONCURRENT_RUNS`); more get 429 with Retry-After.
- 2026-10-30 Confirmed entity ids travel with the brief input: when the promoter picks the artist or the locality in the form, the ids are passed to the agent as hints in the user message (it still verifies them with its own tool call), which removes the free-text locality traps from the web path.
- 2026-10-30 `AGENT_RUNNER=fake` replays a canned trace and returns the sample brief, so Playwright and the Docker smoke test exercise the full web path without Vertex or a Qloo key. It is never enabled in production.
- 2026-10-30 Migrations run at server start (`MIGRATE_ON_START=true`, drizzle-orm migrator) because Cloud Run has no deploy step; the `drizzle/` folder ships in the image. Known markets are upserted and orphaned `running` briefs are marked failed on every start.
- 2026-10-30 Tailwind 4 puts utilities in a cascade layer and MapLibre's stylesheet is unlayered, so `.maplibregl-map { position: relative }` beat the `absolute` utility and collapsed the map to zero height. The map container is sized with `h-full w-full` instead; `maplibre-gl` is excluded from Vite dependency pre-bundling because the pre-bundled copy cannot load its worker in dev.
- 2026-10-30 One shared Qloo client per server process (`getSharedQlooClient`) so the 8 req/s throttle covers concurrent requests; the search routes are thin proxies (`/api/search/artists`, `/api/search/localities`) and the browser never sees the key.
- 2026-10-30 Deployment is scripted in `deploy/cloud-run.sh` but must be run by David: the service account available to the assistant only has Vertex AI permissions (no Cloud Run, Artifact Registry, Cloud Build, Secret Manager or Cloud SQL).
- 2026-10-30 The first live web run showed a silent three-minute gap: the model's first `emit_brief` was rejected by the draft schema (headline and key points over the caps) and the SDK's validation error never reached the trace. Now every tool use that is rejected before running is reported as a warning event with the validation text, the draft caps are roughly doubled (the UI handles long lists), and the `emit_brief` description states the expected lengths.
- 2026-10-30 When the promoter confirmed the locality in the form and the agent skipped `qloo_resolve_locality`, the resolution falls back to the confirmed id (method `entity_id`, "confirmed by the promoter") instead of reporting the locality as unresolved.
- 2026-10-30 Keyed `{#each}` blocks over model-written lists use the index as key: real Qloo tag lists repeat values ("Romantic" twice) and Svelte rejects duplicate keys at runtime.
- 2026-10-30 Hosting is Azure Container Apps (David's call, subscription "Fegora"), not Cloud Run: resource group `rg-gigcast` in `eastus`, a Basic container registry built with `az acr build`, one always-on replica of 1 vCPU / 2 GiB, secrets as Container Apps secrets with the GCP service-account JSON mounted as a file for the Vertex SDK. The Cloud Run script stays in the repo as the alternative.
- 2026-10-30 Postgres is Neon (project `gigcast`, branch `production`); the app uses the pooled connection string, which postgres.js and the Drizzle migrator handle. The Neon CLI's `neon init` added `neon.ts` and the `@neon/config` and `@neon/env` packages; they are dev-only tooling and live in devDependencies so they stay out of the production image.
- 2026-10-30 M3 counterfactual: a second run with no tools at all (`emit_counterfactual` only, effort medium, 8k tokens) answers the lineup and sponsor question in parallel with the main run. The server then matches every LLM-only name against the entities Qloo returned in the main run (accent-insensitive, leading articles dropped, containment for multi-word names) and against the grounded picks, so the panel can say "in Qloo's results", "also picked by the grounded run" or "not in Qloo's results". LLM-only picks are never labeled grounded.
- 2026-10-30 SSE ids are now the `agent_events` row ids, monotonic across the main and counterfactual runs of a brief; subscribers receive an event only after it is persisted, and `Last-Event-ID` resumes both runs from one number. The client dedupes by run id plus sequence.
- 2026-10-30 Sponsor outreach drafts get their own page (`/brief/:id/drafts`) with copy buttons and `mailto:` links that open the promoter's own email client; gigcast never sends anything. Pickers also became blur-safe (`pointerdown` preventDefault on options), close after a pick or Escape, time out after 12 s, and the city pick hands focus to the artist input.
- 2026-10-30 M4 risk layer sources, all verified live: Google News RSS searches per market in Spanish and English (events, security, politics and health, weather and transport, plus artist and venue queries), local outlets with working feeds seeded per market (Prensa Libre, República, Emisoras Unidas; Diario Libre, El Día; La Jornada, Expansión Política, Chilango; TVN; Confidencial) with `TODO(David)` for the ones that 404 or block feeds; Nager.Date for holidays (long weekends computed locally because the LongWeekend endpoint returned 502); Open-Meteo ERA5 archive for the climate on the window dates in the last five years and monthly normals from the last three; US State Department RSS and UK FCDO Atom for advisories. - 2026-10-30 Classification runs on `claude-haiku-4-5` with one `classify_news` tool call per batch of 15 and no thinking: Haiku 4.5 rejects adaptive thinking (verified live) and the task does not need it. Irrelevant items are stored as `other` with severity 1 and filtered out of the feed.
- 2026-10-30 Market risk score: weight ((severity - 1) / 4)^1.5 x confidence x 0.5^(age / 14 days), summed and squashed with 1 - exp(-sum / 4). Calibrated so a week of severity-2 items stays under 25 (quiet) and a couple of fresh severity-4 items read as watch; the first live Guatemala City feed scored 84 with the previous formula and reads about 40 with this one.
- 2026-10-30 The agent gets two more tools: `market_calendar` and `risk_feed`. Their requests are recorded with `source: external` so the Qloo call counters stay honest, and every risk item the model writes must cite a url the feed returned, otherwise the server downgrades it to inferred. `risk_feed` refreshes the store inline (45 s budget) when a market has no items or they are older than 12 hours; the scheduled job (`gigcast-ingest`, every six hours, a curl container posting to `/api/jobs/ingest` with the shared secret) keeps it fresh otherwise.

- 2026-10-30 A redeploy used to kill briefs in flight: the replica got SIGTERM, the server aborted its runs ("Request was aborted.", partial brief) and the next replica marked everything `running` as failed. Now SIGTERM only logs; the Node adapter keeps the process alive while work is pending (`SHUTDOWN_TIMEOUT=600`), the container app has a 600 s termination grace period, orphan cleanup only touches briefs older than 20 minutes, and partial or failed briefs show a "Run this brief again" button.
- 2026-10-30 Design system applied as a visual layer only, in five commits (foundations, brand assets, components, charts and maps, pages). Deviations from the design-system README, each for a measurable reason: the trace well, the table of contents labels, the pricing table header and the source timestamps use `ink-muted` instead of `ink-subtle` because `ink-subtle` on `surface-sunken` measures 4.4:1 in Light and the brief asked for 4.5:1; Sora ships as the static 600 weight (the only weight used) rather than the variable font; the dark token block is duplicated under `prefers-color-scheme: dark` for `:root:not([data-theme=light])` because CSS cannot express that in one selector; a print block inside the token file forces black on white and greys for heat and chart tokens; Tailwind's default palette is removed with `--color-*: initial` so the token grep can fail on any raw palette class; spacing tokens are exposed as `*-space-N` utilities because the bare `*-N` scale stays Tailwind's; the scrollable trace list carries `tabindex="0"` so keyboard users can scroll it; the climate chart maps chart-1 to the low temperature, chart-3 to the high and chart-2 at 45% alpha to precipitation because the README has no climate mapping.
